== 实现要点 ==
- `src/store_tab5.c`（新增，由 selftest.c 末尾 include）：include 前 `#define proj_v3_tmp (*s_v3_ps)` /
  `#define proj_slot (*s_slot_ps)` 让上游声明退化为指针；`#define PROJ_HOST 1` 编入 project.c 的格式层 +
  proj_capture/proj_apply；自有 union 暂存 `proj_tmp`（4,096B：project_t / project_v5_t / raw）；
  `ST_XIP_PTR`/`FM6_BANK_XIP` 走 mmap；`st_read/st_erase/st_prog` 转 HAL。
  启动顺序（ADR-009 §5）：`selftest_snapshot_init()` → `sloop_store_init()`（PSRAM 分配 → HAL
  init → 四槽 fetch），失败只 WARN（引擎/音频照常）。
- 三个指针 + 存储锁 + ready 放 `.noinit`：selftest_restore() 会把本 TU 的 .data/.bss 回滚到 init
  快照（快照在 store init 之前拍），普通静态指针会被抹成 NULL。`s_v3_ps` 用后置 section 属性重声明进
  .noinit（上游该行没有属性）；`s_slot_ps` 继承上游 `proj_slot` 自带的 .noinit 属性。
- 冷启动 .noinit 是垃圾，而 REPL 任务先于 sloop_core_init 启动：`s_init_magic = "SLOP"` 哨兵门控全部
  API，未初始化一律按 no_storage 返回（不碰指针/信号量）。
- 锁序（ADR-009 §3）：保存 = 引擎锁内 capture → 释放 → st_save（擦/写期间不持引擎锁）；加载 = 无锁
  st_load+import → 引擎锁内 proj_apply + song.sel 钳位；`s_store_lock` 串行化所有存储动作（console/
  UI/（后续）自动存档共用）；`STORE STATS` 的 objects 统计经 st_buf，故也持该锁。
- `sloop_hal_storage_fault_armed()` 是本次对 HAL 的唯一新增（3 行；`STORE STATS` 的 armed 字段）。
- console：`STORE STATS` 改用 `sloop_store_stats()`（保留原前缀，追加 armed=）；新增
  `STORE PROJ LIST|SAVE|LOAD|ERASE|HASH`、`STORE LIVEHASH`；`app_console_init` 不再调 HAL init
  （启动顺序归 sloop_store_init；REPL 先起但被哨兵门控）。

== 已知偏差 / 后续 ==
- shim 里 `user_of` 暂未落地：它依赖 `up_used()`/`UP_SLOTS`（upreset.c，预置任务才编入）。`param_kept`、
  `TRK_DEF/trk_def_engine`、`ui_message/ui_say`、`ui.force`、`up_gen`、`sync_reload` 已按上游原样落地。
- 自动存档（`OBJ_AUTOSAVE`：2.5s 空闲 / 20s 间隔 / hash 跳过）、预置银行 `up_boot`、
  `fm6_bank_boot` 属后续任务（spec §4.2 启动顺序里位置已留好：store init 之后）。
- `sloop_store_project_load` 只做 `proj_apply(all=1)` + `song.sel` 钳位（brief Step 5 口径）；上游
  `project_apply` 的 transport_req/panic/`proj_foreign_parts`/sync_reload 属后续任务。
