# 5A 连接打通（FM-1 over USB-MIDI host）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 刷 SLOOP 的 FM-1 插入 Tab5 的 USB-A 口后，Tab5 识别设备、完成 INFO 版本协商、保持 WATCH/PING，设备上的旋钮改动以 CHANGED 推送到 Tab5；全部状态经 console `FM1 …` 命令可读、可脚本断言。

**Architecture:** 两个新组件。`editor_proto` 是纯 C 的帧编解码（无 IDF 依赖，host 可单测）；`usb_fm1` 用 ESP-IDF 原生 `usb_host` 栈自写 MIDI Streaming 客户端——其中的 USB-MIDI 事件包 ⇄ SysEx 帧转换拆成无 IDF 依赖的 `midi_stream.c`（host 可单测），IDF 胶水与最小事务层各自成一个源文件。USB host 开机常驻；5A 不做任何 UI 页面。

**Tech Stack:** ESP-IDF v5.5.5（`usb_host` 库，BSP `espressif/m5stack_tab5` 1.3.3 的 `bsp_feature_enable(BSP_FEATURE_USB)`）、FreeRTOS、gcc host 单测（`scripts/*-test.sh` 先例）、pyserial。

**Spec:** `docs/superpowers/specs/2026-11-26-phase5-sloop-go-alignment-design.md`（§5.3、§6「5A 连接打通」、§7、§9）。协议权威：`third_party/sloop-fm1/web/EDITOR_PROTOCOL.md`；摘要 `docs/research/editor-protocol.md`；固件侧实现 `third_party/sloop-fm1/firmware/src/editor.c`。

## Global Constraints

- 只支持与基线同版的 SLOOP（2.8.x，协议 v12）；不做旧版参数 id 映射。
- 每个请求恰好一个回复（按 cmd 匹配）；cmd 23/24/26/32 是 push，**永不作回复号**；设备同一时刻只缓存一个入站帧 ⇒ 同一时刻只有一个在飞请求。
- WATCH 后设备 3s 无请求即停推送 ⇒ PING 周期 **1000ms**；请求默认超时 **400ms**。
- **绝不发送**固件更新协议帧（`F0 22 24 35 …` / `00 59 …`）。本计划只构造 cmd 1/2/3/22/25 的请求。
- USB host 开机常驻；本计划新建的任务栈一律用 `xTaskCreateWithCaps(…, MALLOC_CAP_SPIRAM)`。内部堆门线不变：`internal_min ≥ 61,440B`、`scripts/selftest-heap.py` 退出码 0；达不到就如实上报读数，**不得自行改 `HEAP_FLOOR`**。
- 5A 不新增 UI 页面、不改页面注册表、不改任何既有 console 命令的输出格式。
- 构建零新增警告；构建/烧录只走 `scripts/build.sh` / `scripts/flash.sh`，不手敲 `idf.py`。
- 设备步骤凡标 **[操作员]** 的，需要人手插拔或拧旋钮。拿不到操作员时：做完其余步骤，在任务报告里写 `WAITING_OPERATOR` 并列出待验证步骤；**不得声称通过**。
- 提交按 AGENTS.md §7：`<type>(<模块>): 中文摘要` + 四标签（fix 另加 Root_Cause/Blast_Radius）；不同 type 不混提。每任务 review clean 后 push。不合并 `main`。

## Review Focus

1. **请求进行中拔线**：`FM1 INFO` 发出后回复永不来 ⇒ 400ms 后返回 `ERR timeout`，互斥量与信号量不残留；重插后下一次 `FM1 INFO` 成功（Task 5 设备步骤）。
2. **非 MIDI 或非 FM-1 的 USB 设备插入 USB-A**：不崩溃、不卡音频，`FM1 STATUS` 仍是 `link=none` 并记一次 `open_fail`（Task 4 设备步骤）。
3. **设备发来的超长或畸形 SysEx / 畸形事件包**：丢弃并计数，绝不越界写（Task 3 host 测试）。
4. **无链路 / host 未启动 / 非法参数时使用 `FM1` 命令**：打印对应 `ERR`、返回非零，控制台最多阻塞一个超时周期（Task 5 设备步骤）。
5. **FM-1 插拔瞬间**：音频不出现 xrun、UI 不卡死（Task 4 设备步骤，`ENG PERF` 前后对比）。

- [ ] **Step 2: 实现 `usb_fm1_start`（本任务只到「枚举并记录」）**

不要调用 `bsp_usb_host_start()`——它建的库任务只调 `usb_host_lib_handle_events`，从不派发 client 事件，而且栈在内部 RAM。按同样的三步自己做：
① `bsp_feature_enable(BSP_FEATURE_USB, true)`；② `usb_host_install()`，配置同 BSP（`skip_phy_setup=false`、`intr_flags=ESP_INTR_FLAG_LOWMED`）；③ 建两个任务：`usb_lib`（优先级 10，循环调 `usb_host_lib_handle_events`，遇 `USB_HOST_LIB_EVENT_FLAGS_NO_CLIENTS` 调 `usb_host_device_free_all()`）与 `fm1_cli`（优先级 4，循环 `usb_host_client_handle_events(client, portMAX_DELAY)`）。两者栈 4096，都用 `xTaskCreateWithCaps(…, MALLOC_CAP_SPIRAM)`。
`fm1_cli` 收到 `USB_HOST_CLIENT_EVENT_NEW_DEV`：`usb_host_device_open` → 读设备描述符与配置描述符 → `ESP_LOGI` 打印 `VID/PID` 与每个接口的 `class/subclass` → 读 iProduct 字符串描述符存进 `product` → 记 `vid/pid` → **本任务不 claim**，`usb_host_device_close`。`DEV_GONE`：清 `vid/pid/product`。
`usb_fm1_send_frame` 本任务恒返回 `ESP_ERR_NOT_SUPPORTED`；`on_frame`/`on_link` 本任务不调用。

- [ ] **Step 3: console `FM1 STATUS`（`main/console.c`）**

照 `disp_command` 的写法注册 `FM1` 命令，本任务只支持 `STATUS`：
host 未启动 ⇒ `FM1 STATUS ERR no_host`；否则 `FM1 STATUS link=<none|ready> vid=0x%04X pid=0x%04X product=%s rx=%u tx=%u drops=%u open_fail=%u`（无设备时 vid/pid 为 0x0000、product 为 `-`）。成功返回 0，`ERR` 返回 1。其它子命令先回 `FM1 ERR invalid`。

```c
esp_err_t fm1_session_info(fm1_info_t *out, TickType_t timeout);              /* 发 INFO 并更新缓存 */
esp_err_t fm1_session_get(uint8_t scope, uint8_t id, int16_t *value, TickType_t timeout);
esp_err_t fm1_session_set(uint8_t scope, uint8_t id, int16_t value, int16_t *clamped, TickType_t timeout);
esp_err_t fm1_session_watch(uint8_t on, uint8_t *replied, TickType_t timeout);
esp_err_t fm1_session_ping(uint32_t *roundtrip_us, TickType_t timeout);
void fm1_session_stats(fm1_session_stats_t *out);
void fm1_session_stats_reset(void);
/* 无链路 ESP_ERR_INVALID_STATE；超时 ESP_ERR_TIMEOUT；回复 cmd 不符按 stray 计后继续等到超时。 */
```

- [ ] **Step 1: `fm1_session.c` — 请求/回复**

一个互斥量保证单在飞；请求路径：持锁 → `usb_fm1_send_frame` → 等 reply 信号量（`timeout`）→ 核对回复 cmd → 放锁。`on_frame` 回调（`usb_lib` 上下文）：`edp_frame_parse` 失败 ⇒ `stray++`；`edp_cmd_is_push` ⇒ 计数并记 `last_*`（`last_v` 仅对 CHANGED/TRACK_CHANGED 用 `edp_v14_dec(args[2], args[3])`）；否则存进 reply 槽并给信号量。共享状态用 `portMUX_TYPE` 临界区保护。

- [ ] **Step 2: 保活与自动协商**

`fm1_session` 任务每 1000ms：`link` 为真 ⇒ 发 PING（400ms 超时，失败 `timeouts++`）。`on_link(true)` ⇒ 任务立即发 INFO（写缓存）再发 `WATCH 3`（记 `watch_on/watch_val`）；`on_link(false)` ⇒ `watch_on=false`。`fm1_session_watch(0,…)` 成功后不再自动重开，直到下一次链路重建。

- [ ] **Step 3: console `FM1` 子命令（`main/console.c`，替换 Task 1 的占位分支）**

输出格式逐字（脚本要断言）；成功返回 0，`ERR` 返回 1：

| 命令 | 成功输出 | 失败输出 |
|---|---|---|
| `FM1 STATUS` | Task 1 的行，追加 ` watch=<0|3> info=<yes|no> proto=<n|->` | `FM1 STATUS ERR no_host` |
| `FM1 INFO` | `FM1 INFO version="%s" nengines=%u p_count=%u g_count=%u nstep=%u pe0=%u ntrk=%u proto=%u engines=A\|B\|…` | `ERR no_link` / `ERR timeout` / `ERR bad_reply` |
| `FM1 GET <scope> <id>` | `FM1 GET scope=%u id=%u value=%d` | `ERR invalid` / `ERR no_link` / `ERR timeout` |
| `FM1 SET <scope> <id> <v>` | `FM1 SET scope=%u id=%u value=%d`（回复里的钳位值） | 同上 |
| `FM1 WATCH <0\|1\|3>` | `FM1 WATCH on=%u`（回复值） | 同上 |
| `FM1 PING` | `FM1 PING ms=%u` | `ERR no_link` / `ERR timeout` |
| `FM1 EVENTS` | `FM1 EVENTS total=%u changed=%u reload=%u step_changed=%u track_changed=%u timeouts=%u stray=%u last=none` 或 `last=cmd=%u scope=%u id=%u value=%d` | `ERR no_host` |
| `FM1 EVENTS CLEAR` | `FM1 EVENTS cleared` | — |
| 其它 | `FM1 ERR invalid` | — |

非法范围：`scope > 1`、`id ≥ 200`、`v` 不在 −8192..8191、`WATCH` 的值不在 {0,1,3} ⇒ `ERR invalid`，不发任何帧。默认超时 `pdMS_TO_TICKS(400)`。`FM1 EVENTS` 的打印用快照（临界区内拷贝）。

- [ ] **Step 4: `main.c` 启动会话**

`usb_fm1_start()` 之后调用 `fm1_session_start()`；失败只 `ESP_LOGE`（此时 `FM1 INFO/GET/…` 回 `ERR no_host`）。

- [ ] **Step 6: 设备核对 **[操作员]**：FM-1 已插在 USB-A 口**
